# 🏓 卓球大会ポータル（Google Apps Script）

Google スプレッドシートで参加者・試合結果を管理し、Web ページから選手が試合結果を入力、保護者などが結果を閲覧できるポータルです。

1つの Web アプリで **複数の大会** を扱えます。大会は Web 上で作成でき、大会ごとに専用のスプレッドシートが自動で作られます。選手・閲覧者は最初に大会一覧から大会を選びます。

リーグ戦（予選）→ 上位・下位トーナメント（決勝トーナメント）まで対応しています。

## 機能

| 画面 | 内容 |
| --- | --- |
| 大会一覧（最初の画面） | 公開中の大会を一覧表示。選んだ大会のトップへ。下に小さく「大会の作成・管理（システム管理者）」 |
| 大会の作成・管理 | システム管理者パスワードで入る。大会の作成（スプレッドシートを自動作成、または既存シートの URL を指定）、名前・開催日の編集、公開/非公開、一覧から削除、各大会の管理者メニューへ |
| 大会トップ | 「選手用（試合結果の入力）」「結果確認用（保護者・観覧）」の2つのボタン。下に小さく「この大会の管理者メニュー」 |
| 試合を選ぶ | 「リーグ番号で選ぶ」「名前で選ぶ」（名前・所属・くじ番号で検索） |
| 試合一覧 | 試合中 → これからの試合 → 終了した試合 の順に表示。名前から選んだ場合はその選手の試合だけ表示（切替可）。一番下に「結果（順位表）を見る」リンク |
| 結果入力（選手用のみ） | 各セットの得点を入力（獲得セット数は自動計算して表示）。途中でも保存可 |
| 順位表 | 順位表 + 対戦表（星取表）。セル（例: 2-1）をタップすると試合の詳細、選手用なら一番下に「修正する」ボタン |
| 大会の管理者メニュー | スプレッドシートを開く、大会への直接リンクのコピー、設定の変更、くじ番号の自動割当、リーグ戦作成、当日参加選手の追加、順位シート更新、テスト用サンプル選手の追加 |

### 開催ステータス・参加者リスト・ルール

| ステータス | 選手・保護者が見られるもの |
| --- | --- |
| 開催前 | **参加者リスト**（「参加者」シートの名前・所属）と**ルール**のみ。試合の入力・閲覧はできない（サーバー側でも試合データを返さない） |
| 開催中 | 試合の結果入力・閲覧（これまでどおり）＋参加者リスト・ルール |
| 終了 | 閲覧のみ（結果の入力はできない）＋参加者リスト・ルール |

- ステータスは管理者メニューの「公開ステータス」で切り替える（「設定」シートの「開催ステータス」にも保存）。新しく作った大会は「開催前」から始まる
- **大会情報**（場所・住所・開始時間・当日の連絡先・メモ）は管理者メニューの「大会情報」で編集。開催前から大会トップに表示（住所から Googleマップのリンク、電話番号・メールはタップで発信／メール作成）
- ルールは管理者メニューの「ルール」で編集（「# 」で見出し、「- 」「・」で箇条書き）。開催前から大会トップの「📖 ルール」で公開
- 大会一覧にもステータスが表示される

### トーナメント

| 項目 | 内容 |
| --- | --- |
| 振り分け | 各リーグの上位 N 名（設定の「上位トーナメント進出人数」）→ 上位トーナメント、それ以外 → 下位トーナメント |
| シード | ①リーグ内順位（1位の選手 → 2位の選手 …）②勝率 ③セット率 ④獲得セット数 の順。完全に同じならランダム |
| 組み合わせ | 標準的なシード配置（第1シードと第2シードは決勝まで当たらない）。人数が2の累乗でない場合は上位シードが1回戦不戦勝。1回戦で同じリーグの選手どうしが当たらないように入れ替え |
| 台の割り当て | 設定の「台の数」の台を上位・下位で共用。台が空くたびに「残り試合数 ÷（その山で台を使っている試合数 + 1）」が大きい方の山の試合を入れる＝**残り試合数に比例して台を配分**（例: 上位8名・下位12名・台4台なら最初は下位3台・上位1台）。それぞれの山の中では対戦相手が決まった順。上位・下位がほぼ同時に終わるように進む。「次の試合」の一覧は目安（結果が入るたびに配分を計算し直す） |
| 進行 | 結果を保存すると勝者が次の試合に進み、空いた台に次の試合が自動で入る。途中経過の保存も可 |
| 一括で試合中 | 選手用の「台の状況」で、呼び出し中の台の □ にチェックを入れて「選択した試合を『試合中』にする」でまとめて試合中に移せる（「すべて選択」あり。既に変更済みの試合は自動で対象外） |
| 連戦の回避 | 直近に終わった試合（台の数の半分）に出た選手を「休憩中」とし、空いた台には休憩中の選手がいない試合を優先して入れる。待っている試合がすべて休憩中の選手を含む場合は、台を空けないようにその試合を入れる |
| 試合ごとのセット数 | トーナメントの入力画面の「この試合のセット数」（1/3/5/7）で、その試合だけ変更できる（得点なしでも保存可）。初期値は設定の上位/下位トーナメントのセット数 |
| 決勝 | 台は割り当てない（台と開始時間は大会スタッフが個別に案内）。対戦相手が決まると、トーナメント画面の「決勝」欄に「案内待ち」として表示。結果入力は他の試合と同じ |
| 3位決定戦 | 上位・下位それぞれで、準決勝の敗者どうしが対戦（設定「3位決定戦」で行う/行わないを選択。作成済みのトーナメントにも後から追加可）。決勝より先に台に呼ばれる。3名の山など準決勝に不戦勝がある場合は作らない |
| 棄権（途中で帰る選手） | 「参加者」シートの「棄権」列にチェックを入れると、トーナメントでは名前に取り消し線と「棄権」が付き、その選手の試合は不戦敗（相手の不戦勝、台は使わない）。作成前にチェックした選手もシードどおりに山に入り、不戦敗になる。チェックを外すと、次の試合が始まっていなければ元に戻る |
| 修正 | 終了した試合の勝者を変えると、次の試合の選手も自動で差し替わる（次の試合がまだ始まっていない場合のみ。始まっている場合は先に次の試合の結果を消す） |

画面:

- **選択画面**: 「🏆 トーナメント / リーグ戦」の切り替え。トーナメントでは「上位トーナメント」「下位トーナメント」と、名前での検索（選手ごとに上位T / 下位T を表示）
- **トーナメント画面**: 上位 / 下位のタブ、**台の状況**（「📣 呼び出し中（新しく割り当てた台・青）」と「🏓 試合中（オレンジ）」を上下に分けて表示、空いている台は下に一覧）、**次の試合**（呼出順）、**トーナメント表**（シード順位・スコア・台番号つき。横にスクロール。3位決定戦は決勝の下）、優勝・準優勝・3位
- 名前から選ぶと、その選手の試合（台番号・状態つき）が上に表示され、トーナメント表でも強調表示されます
- 選手用では試合をタップすると結果入力、閲覧用では詳細表示のみ

### パスワードは2種類

| 種類 | 保存場所 | できること |
| --- | --- | --- |
| システム管理者パスワード | スクリプトプロパティ（初回アクセス時に Web で設定） | 大会の作成・編集・非公開・削除。全大会の管理者メニューにも入れる |
| 大会管理者パスワード | 各大会の「設定」シート | その大会の設定変更・リーグ戦作成など |

### 結果入力時のチェック

- 獲得セット数は各セットの得点から自動で計算されるので、食い違いは起きません
- リーグ戦は、入力された得点から自動で「試合中」「終了」を判定（途中の得点で保存すると「試合途中ですね？」と確認）
- **トーナメント**の入力画面では **進捗（試合前 / 試合中 / 試合終了）** を選ぶ。得点を入力すると自動で切り替わる
  - 試合を始めたら「試合中」で保存（得点なしでも可）→ トーナメントでは台が「試合中」の欄に移る
  - 得点なし・勝敗が決まっていないのに「試合終了」→ エラー（全セットの得点の入力を求める）
  - 得点があるのに「試合前」、勝敗が決まっているのに「試合中」→ エラー
- 片方だけ入力されたセット・同点・勝敗決定後の余分なセット・途中の空欄 → 警告
- 卓球のルール上ありえない得点（11-10、10-8 など） → 「このまま続ける / 入力に戻る」を確認
- **どちらも規定セット数に達していない** → 「試合途中ですね？」と確認。
  途中なら「途中経過として保存」、終わっているなら「入力に戻る」で全セットを入力してもらう
- 決着している場合は「〇〇さんの勝ち 2-1 で保存します」と最終確認
- 終了した試合も「修正」から何度でも直せます。結果を消して「未実施」に戻すことも可能
- 閲覧用で入った場合は、入力・修正ボタンは一切表示されません

### 順位の決め方

1. 勝率（勝ち ÷ 終了した試合数）
2. セット率（獲得セット ÷ 失セット。失セットが 0 の場合は ♾️）
3. 獲得セット数
4. 当該選手間の直接対決で勝った選手が上（3名以上並んだ場合は、その選手間での勝数 → まだ並ぶ選手間で再度比較）

それでも決まらない場合（直接対決が未実施など）は同順位（「2=」のように表示）。
各リーグの上位 N 名（設定の「上位トーナメント進出人数」、初期値 2）を「上位T」、それ以外を「下位T」と表示します。全試合終了までは「暫定順位」と表示されます。

### 同時アクセス（約100名）への対策

- 閲覧系のリクエストはスプレッドシートを読まず、`CacheService` に置いた JSON をそのまま返す
- 結果保存時は `LockService` で排他し、保存と同時にキャッシュ・順位シートを作り直す（保存直後に100人が開いても、シートの読み込みが集中しない）
- **同じ試合を2人が同時に編集した場合**は、後から保存した人に「他の人が先に更新しました」と表示し、上書きするか最新を見るかを選べる（版番号による楽観ロック）
- 試合一覧・順位表は 45 秒ごとに自動更新（入力中・ダイアログ表示中は更新しない）。🔄 ボタンで手動更新も可
- スプレッドシートを手で編集すると `onEdit` でキャッシュが破棄され、すぐに反映されます

## スプレッドシートの構成

| シート | 編集する人 | 内容 |
| --- | --- | --- |
| 参加者 | スタッフ | `名前` `所属` `学年` `参加確認`(☑) `支払確認`(☑) `くじ番号` `リーグ`(自動) `備考` `棄権`(☑・途中で帰った選手) |
| 設定 | スタッフ / Web | 大会名、リーグ戦の数、各リーグの標準選手数、リーグ戦・上位T・下位Tのセット数、上位T進出人数、管理者パスワード、選手入力パスコード |
| リーグ | 自動 | どのくじ番号がどのリーグか |
| 試合 | 自動 | 1試合1行。状態（未実施 / 試合中 / 終了）、獲得セット、各セットの得点（"11-8" 形式）など |
| 順位 | 自動 | リーグごとの順位・成績・進出先 |
| トーナメント | 自動 | 上位・下位トーナメントの全試合（1試合1行）。回戦、選手とシード、状態（待機 / 未実施 / 試合中 / 終了 / 不戦勝）、得点、台、呼出順 |

- **リーグ戦の対象**になるのは「参加確認 ☑」「支払確認 ☑」「くじ番号あり」の選手です。
- 当日参加の選手は、参加者シートの最後の行に追加してください。リーグ作成後に追加した選手は自動でリーグに入ります（下の「遅れて来た選手」参照）。
- くじ番号を引いていない選手には、管理者メニュー（またはシートのメニュー）の「くじ番号を自動割当」で空いている番号をランダムに付けられます。
- 画面の名前は「名前（所属・学年）」で表示されます（学年は数字だけなら「2年」のように表示。「中2」などはそのまま）。既存のシートに「学年」列が無い場合は、管理者メニューを開くと右端に追加されます（列の位置は移動して構いません）
- 選手名の誤字は参加者シートで直せば、Web の表示にもすぐ反映されます（くじ番号で紐付けています）。

## セットアップ手順

スプレッドシートに紐付けない「単独の Apps Script プロジェクト」として作ります（スプレッドシートは大会作成時に自動で作られます）。

1. [script.google.com](https://script.google.com/) で「新しいプロジェクト」を作成します。
2. `src/` 内のファイルをすべてエディタに作成し、内容を貼り付けます。
   - スクリプト（`.gs`）: `Code` `Registry` `Sheets` `Logic` `Data` `Api` `Admin` `Tournament` `Log`
   - HTML: `Index` `Styles` `App`
   - `appsscript.json`: 「プロジェクトの設定 → 『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにして内容を置き換え
   - [clasp](https://github.com/google/clasp) を使う場合は `rootDir` を `src` にして `clasp push` でも可
3. エディタで関数 `authorize` を選んで「実行」し、権限を承認します（スプレッドシートの作成・編集、トリガー）。
4. 「デプロイ → 新しいデプロイ → 種類: ウェブアプリ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**（Google アカウント不要で保護者も見られる）
5. 発行された URL を開き、「大会の作成・管理（システム管理者）」から **システム管理者パスワード** を設定します（初回のみ。最初に設定した人がシステム管理者になるので、デプロイしたらすぐに設定してください）。
6. 「新しい大会を作成」で大会名・開催日・大会管理者パスワードを入力して作成します。
   - 空欄なら新しいスプレッドシートが自分の Google ドライブに作成されます。
   - 事前に選手名を入れたスプレッドシートを使う場合は、その URL を貼り付けます（足りないシートや見出しは自動で追加されます。「参加者」シートの1行目に `名前` `参加確認` `支払確認` `くじ番号` の見出しが必要です）。
7. 作成した大会の「📄 シート」から参加者シートを開いて選手名を入力します。
8. 選手・保護者には Web アプリの URL（大会一覧が出ます）か、大会ごとの直接リンク（`…/exec?t=大会ID`、管理画面の「🔗 リンク」でコピー）を QR コードなどで共有します。

> コードを変更したら「デプロイを管理 → 編集 → バージョン: 新バージョン」で更新すると、URL は変わりません。

- 終わった大会は「非公開にする」で一覧から隠せます（直接リンクでは引き続き閲覧可能）。「一覧から削除」してもスプレッドシートは消えません。
- スプレッドシートを直接編集したときに Web 表示へすぐ反映されるよう、大会作成時に編集トリガーを自動で設定します（Apps Script のトリガー上限は1ユーザーあたり20個なので、大会が20を超える場合は古い大会を「一覧から削除」してください。削除しない場合も、表示は最長10分で更新されます）。

### 試しに動かす

大会を作成したら、その大会の管理者メニューの「その他 → テスト用サンプル選手を追加」で、参加・支払済み・くじ番号付きの選手が 18 名追加されます。その後「リーグ戦作成」を押すと、リーグと試合が作成されます。

## 独自ドメインで公開する（Cloudflare Worker）

独自ドメイン（例: `https://portal.example.com/`）にアクセスすると、Apps Script のウェブアプリを全画面で埋め込んだページを返す方式です。アドレスバーは独自ドメインのまま、結果の入力などはこれまでどおり動きます。

> Google のサーバーを中継（リバースプロキシ）する方式は、結果の保存が動かなくなりやすいため使いません。

### 準備
- 独自ドメインの DNS を Cloudflare で管理していること
- ウェブアプリの URL を変えないこと（更新は「デプロイを管理 → 編集 → 新バージョン」。「新しいデプロイ」を作ると URL が変わるので、その場合は Worker の `GAS_URL` も変更）

### 手順（ダッシュボードで作る場合）
1. Cloudflare のダッシュボード →「Workers & Pages」→「作成」→「**Start with Hello World!**」を選び、名前（例: `tabletennis-portal`）を入れて「デプロイ」
   - 「Upload and deploy」（ファイルをドラッグ＆ドロップする画面）は静的ファイル用なので使わない。`worker.js` や `wrangler.toml` はアップロードしない
2. 「コードを編集」で、`cloudflare/worker.js` の中身をすべて貼り付けて「デプロイ」
3. 「設定 → 変数とシークレット」で次を追加（`GAS_URL` は管理画面「大会の作成・管理」の「公開URL」欄の下に表示される Apps Script の URL）
   - `GAS_URL` … `https://script.google.com/macros/s/…/exec`
   - `SITE_TITLE` … ページのタイトル（LINE などで共有したときのタイトルにもなる）
   - `SITE_DESC`（任意）… 共有時の説明文 / `OG_IMAGE`（任意）… 共有時の画像の URL
4. 「設定 → ドメインとルート → 追加 → カスタムドメイン」で `portal.example.com` などを追加
5. Web の「大会の作成・管理（システム管理者）」→「公開URL（独自ドメイン）」に `https://portal.example.com/` を入力して保存
   - 各大会の「🔗 リンク」「この大会の直接リンクをコピー」が `https://portal.example.com/?t=大会ID` になります

コマンドで公開する場合は `cloudflare/wrangler.toml` の値を書き換えて `cd cloudflare && npx wrangler deploy` を実行します。

### 公開後の確認
スマホ（iPhone の Safari / Android の Chrome）とパソコンで、`https://独自ドメイン/` と `https://独自ドメイン/?t=大会ID` を開き、大会の表示・結果の保存・リンクのコピーができることを確認してください。

### 制限
- 個人の Google アカウントで作ったウェブアプリでは、上部の「このアプリケーションは Google Apps Script のユーザーによって作成されたものです」という表示は消せません
- 大会の指定は `?t=大会ID` で行います（`/大会名` のようなパスは使いません）

## 更新ログとアクセスログ

### 更新ログ（各大会のスプレッドシートの「更新ログ」シート）
結果の入力・修正・消去、途中経過、セット数の変更、一括「試合中」、管理者の操作（公開ステータス変更・リーグ戦作成・トーナメント作成・設定保存・ルール保存・選手追加）を1行ずつ記録します。

| 列 | 内容 |
| --- | --- |
| 日時 / 種類 / 試合ID / 試合 / 操作 | 例: リーグ戦 / L1-01 / リーグ1 第1試合 A vs B / 結果を修正 |
| 変更前 / 変更後 | 例: 終了 2-0（11-9, 11-3） → 終了 2-1（11-9, 3-11, 11-3） |
| 端末 | ブラウザごとにランダムに付ける番号（同じ端末からの操作かどうかが分かる） |
| IPアドレス / IP確認 | 独自ドメイン（Cloudflare Worker）経由で、連携キーを設定している場合に記録。「確認済」は Worker の署名を確認できたもの（書き換えられていない） |
| ブラウザ | ブラウザの種類（User-Agent） |

### アクセスログ（Cloudflare Worker）
ページを開くたびに、日時・IPアドレス・国/地域/都市・ブラウザ・URL（大会ID）・参照元を記録します。結果の保存などの通信は Google に直接届くため、アクセスログには「ページを開いた記録」だけが残ります（保存の記録は更新ログ）。

- **Workers Logs**（設定は1回だけ）: Worker の「設定 → 可観測性（Observability）」で「Workers Logs」を有効にする → Worker の「ログ」タブで検索（無料プランは3日間保存）
- **D1 に長期保存**（任意）:
  1. 「ストレージとデータベース → D1 → データベースを作成」（名前は例: `tabletennis-access-log`）
  2. Worker の「設定 → バインディング → 追加 → D1 データベース」で、変数名 `ACCESS_DB`、作成したデータベースを選ぶ
  3. Worker の「設定 → 変数とシークレット」で `LOG_VIEW_KEY`（種類: シークレット、推測されにくい文字列）を追加
  4. `https://独自ドメイン/__access-log.csv?key=LOG_VIEW_KEY の値&days=7` を開くと、直近7日分を CSV（Excel で開ける）でダウンロード（days は1〜366）

### 更新ログに IP アドレスを残す設定
1. Web の「大会の作成・管理（システム管理者）」→「アクセスログ連携キー」で「🎲 ランダムに作成」→「連携キーを保存」
2. 同じ値を Worker の「設定 → 変数とシークレット」に `LOG_SECRET`（種類: シークレット）として追加
3. 以降、独自ドメインから開いた人の操作は、更新ログに IP アドレスが「確認済」で記録されます（Apps Script の URL を直接開いた場合は IP なし）

> IP アドレスは、他の情報と組み合わせると個人を特定できる場合があります。ルールのページなどに「アクセス記録（IPアドレス等）を取得し、大会運営・不正対応の目的にのみ使用します」などと記載しておくことをおすすめします。

## 当日の流れ

1. 受付で「参加者」シートの **参加確認**・**支払確認** にチェック、くじを引いてもらい **くじ番号** を記入
2. Web の大会トップ下の「この大会の管理者メニュー」でパスワードを入力し、リーグ戦の数・各リーグの標準選手数・セット数などを設定
   - 参加・支払済みでくじ番号が空欄の選手には、リーグ作成時に自動で番号が付きます
   - 対象人数と標準選手数から「推奨リーグ数」と各リーグの人数が表示されます（割り切れない場合は ±1 名で調整）
3. 「リーグ戦作成」をクリック → くじ番号がランダムにリーグへ振り分けられ、総当たりの試合表ができます
   - すでに結果が入力されている場合は、消えてもよいか確認が出ます
4. 遅れて来た選手は、「参加者」シートの最後の行に名前を書いて **参加確認・支払確認にチェック** を付けるだけで、自動でリーグに追加されます
   - 追加先は **人数が一番少ないリーグ**（同じ人数のリーグが複数あればその中からランダム）。そのリーグの全選手との試合が自動で作られます
   - くじ番号が空欄なら、空いている番号が自動で付きます（自分で番号を書いてもOK。書く場合はチェックを付ける前に書いてください）
   - 追加すると「リーグ」列にリーグ番号、「備考」列に「自動追加: リーグ3（時刻）」が書き込まれます
   - 自動で追加されたあとは、その選手のくじ番号を書き換えないでください（試合と選手の紐付けに使っています）
   - 入力済みの試合結果はそのまま残ります
   - 自動追加をやめたい場合は、設定の「遅れて来た選手をリーグに自動追加」を「しない」にして、管理者メニューで追加先を選んで手動で追加します
5. 選手は「選手用」から自分の試合を選んで結果を入力。保護者は「結果確認用」で閲覧
6. リーグ戦が終わったら（管理者メニューに各リーグの終了状況と「✅ すべてのリーグ戦が終了しました」が表示されます）、「🏆 トーナメント表を確認して作成」をクリック（台の数・上位/下位のセット数・3位決定戦は設定で変更できます）
   - トーナメントは自動では作成されません。まず **作成前の確認画面** が表示されます: リーグ戦の終了状況、注意事項（未終了のリーグ・作り直し）、シード順、トーナメント表、最初に台に呼び出す試合
   - 問題がなければ「この内容で作成」→ 確認ダイアログで「作成する」。確認画面と同じ組み合わせで作成されます
   - 確認画面を開いた後にリーグ戦の結果や設定が変わった場合は作成されず、確認画面からやり直しになります（確認画面の有効期限は30分）
   - 選手はトーナメント画面の「台の状況」で自分の台を確認して試合をし、結果を入力します。結果を保存すると次の試合が空いた台に自動で入ります
   - トーナメント作成後は、遅れて来た選手のリーグへの自動追加は行いません
   - 台が使えなくなったなどで台の数を変える場合は、設定の「台の数」を変更して保存すると割り当てをやり直します（試合中の台はそのまま）

選手以外の入力を防ぎたい場合は、設定の「選手入力パスコード」を設定してください（選手用に入るときに入力を求めます。会場で口頭や掲示で伝える想定です）。
